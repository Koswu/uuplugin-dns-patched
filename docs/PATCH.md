# 补丁原理与实测记录

## 二进制修补原理

本项目通过直接修改 ELF 二进制中构造 iptables 命令的常量字符串与模板，在不改变原有指令长度与函数签名的前提下，为规则追加 Tailnet 地址段排除条件。

### 修改偏移及逻辑

- **IPv4 规则模板**（偏移 `0x3e0998`、`0x3e0b00`）：
  - 针对 DNS DNAT 添加与删除模板，保持 `printf` 参数顺序不变，追加 `! -d 100.64.0.0/10` 排除。
- **IPv6 规则模板**（偏移 `0x3e1410` - `0x3e1470`）：
  - 针对 DNS DROP 添加与删除模板，追加 `! -d fd7a:115c:a1e0::/48` 排除。
- **指令立即数填充**：
  - 微调四组 IPv6 立即数尾部为空格填充，确保二进制总长度（官方版 5,210,480 字节）与代码布局完全不变（共修改 285 字节）。

详细替换位置与原始字节映射参见 [patch_uuplugin_tailnet.py](../patch_uuplugin_tailnet.py)。

## 隔离环境测试记录

测试环境：Arch Linux (Incus VM)，UU 14.2.2，Tailscale 1.104.2，NetworkManager。

### 1. 对照测试（原版未打补丁）
- 启动 UU 加速后，全局 DNS 被重定向，IPv4 MagicDNS 及 IPv6 内网 DNS 均超时不可达；
- 手动提前插入静态 iptables 规则无效，因为 UU 会将新规则强制插入到链首。

### 2. 补丁版本验证
- **加速启停与规则生命周期**：在 UU App 中启动加速、停止加速、切换节点，规则均能正常注入与清理，无规则残留；
- **DNS 解析矩阵（94 项测试通过）**：
  - MagicDNS 双栈 UDP/TCP 解析正常；
  - Tailnet 内部服务 A/AAAA 记录解析正常；
  - Steam 加速流量（走 `tun163`）与公共域名解析正常；
  - 内网目标流量正常路由至 `tailscale0`。
